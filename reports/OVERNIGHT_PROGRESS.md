## 4. Major verified research findings

Top verified findings (full ranked list of 16 with tags in
`reports/research_findings.md`):

1. **Fossil generation peaked in 2024 and fell in 2025** on the Ember
   91-country matched panel (16,716.0 → 16,620.0 TWh, −0.57%), while clean
   generation grew +7.2% (12,082.9 → 12,953.2 TWh). [verified]
2. **Clean share of generation rose 38.84% → 43.80%** (2020 → 2025, matched
   panel); wind+solar alone grew 2,414.4 → 5,420.8 TWh (+124.5%). [verified]
3. **Clean covered 109.9% of 2025 demand growth** on the matched panel —
   the only year above 100% (2021–2024: 35.6 / 73.9 / 77.4 / 76.8%). [verified]
4. **The 2025 global fossil dip was a regional reshuffle:** US +91.2 TWh,
   China −80.5, India −49.3 — the world total barely moved. [verified]
5. **US 2025 coal rebound:** sector-98 consumption 373.3 → 415.4M short
   tons (+11.3%), led by electric power (IN +4.06M st, KS +3.73M, MO
   +3.72M, IA +2.75M), while industrial coal fell −6.0% and delivered
   prices stayed flat ($46.45 → $45.56/st). 2025 receipts ran −25.5M st
   (stockpile drawdown, not build-up). [verified; causation open — H-US]
6. **Asia coexistence:** China coal generation 5,836 TWh (57.4% of world,
   2024) still 54.4% of its own generation in 2025, while wind+solar grew
   +46% YoY (1,836 → 2,310 TWh); India coal share 71.2%. [verified]
7. **Concentration:** top-5 producers = 83.6% of world coal production;
   top-5 generators = 84.5% of coal generation (2024). [verified]
8. **Exporter decoupling:** Indonesia production +48.2% vs domestic
   generation +26.3% (2020→24); Brazil +12.4% vs −20.4% — production is a
   seaborne-demand bet, not a domestic-retirement bet. [verified]

The central tension, stated honestly: in **share** terms clean is winning
globally; in **absolute** terms coal volumes grew through 2024 and were ~flat
in 2025 on the EI panel. The two sources do not contradict once panel
definitions are controlled (matched 91-country vs 109 listed countries,
aggregates excluded) — see "Contradictions surfaced" in the findings report.

## 5. Dashboard features implemented

Stack: React 18.3 · TypeScript (strict) · Vite 5 · globe.gl + three ·
echarts · d3-geo + topojson (world-atlas, us-atlas) · vitest.

- **3D globe** — country polygons from world-atlas; choropleth across the
  8 registered layers: clean share, renewable TWh, demand TWh, coal
  generation TWh, coal share, coal production Mt, coal TES EJ, carbon
  intensity g/kWh. Null values render as no-fill, never as zero.
- **Year selector 2020–2025** with per-year domain scaling · **country
  search** · **legend** with clamp notes · hover tooltips · coal-change
  diverging scale (TWh vs previous year).
- **Country explorer panel** — click a country for its metrics, series, and
  cross-dataset rows (Ember + EI joined per country-year).
- **US drill-down (mandatory Phase 7)** — clicking the United States
  switches to a 2D US map (us-atlas, 50 states + DC + PR): sector pills
  select one base sector (1, 2, 3, 8, 9, 10) or safe sums of base sectors
  ("Electric power 1+2+3", "All base sectors"); EIA's overlapping aggregate
  sectors 94/98 live in a separate aggregates table and are **never combined**
  with the state map, so double-counting is structurally impossible. State
  panel gives per-sector detail, share of national consumption, and a
  US top-15 overview.
- **Industry research panel (Phase 8)** — evidence cards per industry tab
  (coal / clean / utility / gas / cross-country), each item tagged
  `verified` / `interpretation` / `hypothesis`; **no hard-coded
  recommendations, ratings, or price targets**.
- Data is served from `public/data/*.json`, exported deterministically from
  `data/processed/` by `dashboard/scripts/export_dashboard_data.py`.
- Light/dark theme; responsive top bar.

## Follow-up fix (2026-11-05): dashboard JSON load failure

A browser load failure was reported and fixed:
`Failed to load data: Unexpected token 'N', ..."price": NaN, "r"... is not
valid JSON`.

**Root cause.** Python's `json.dumps` defaults to `allow_nan=True`, which
serializes `float('nan')` as the bare token `NaN` — not valid RFC 8259 JSON,
and rejected by browser `JSON.parse`. Two export paths emitted it:
- `export_us_state()` and `export_us_aggregates()` built record dicts with
  raw pandas/NumPy values and applied **no** NaN cleaning at all.
- `export_country_year()` cleaned only the nested `ember`/`ei` dicts (via
  `_clean`), leaving the top-level `coal_share` (and any other top-level
  null) uncleaned.
The `us_state_year.json` (1,387), `us_aggregates.json` (88), and
`country_year.json` (958) files all contained bare `NaN` tokens; `geo.json`
was clean.

**Secondary bug found while fixing.** `export_country_year()` read
`zero_generation_flag` and `carbon_intensity_precision_limited` from the
processed table via `r.get(...)`, but those two columns never made it into
`analysis_country_year.csv` — so the flags were **always exported as
`False`** (silent, not a parse error). The flags exist in the cleaned Ember
table and are documented in the data dictionary, but `process.py` dropped
them.

**Changes made.**
- `src/process.py` — `build_country_year()` now carries
  `zero_generation_flag` and `carbon_intensity_precision_limited` through
  from the cleaned Ember table (source of truth), so the flags hold real
  values instead of a constant `False`.
- `src/make_reports.py` — data dictionary documents the two carried flags.
- `dashboard/scripts/export_dashboard_data.py` — replaced scalar-only
  `_clean` with a recursive `_sanitize` (dicts, lists, NumPy/pandas
  scalars; NaN/±Inf→`null`; real `0` preserved; strings like `"NA"` left
  alone). Every `export_*` returns `_sanitize(...)` so the invariant is at
  each function boundary. `main()` serializes with `allow_nan=False` (hard
  backstop — a surviving non-finite raises instead of writing a bad file)
  and re-parses each written file with a standards-compliant decoder that
  rejects bare `NaN`/`Infinity` tokens.
- `tests/test_dashboard_export.py` (new) — regression tests for
  missing coal prices, missing inventories, non-finite values (Python +
  NumPy), nested data, real-zero preservation, determinism, and strict
  parse of every generated file.
- `dashboard/src/viz/format.test.ts` (new) — pins that missing values render
  as the em-dash (never `0`) in the country/state panels and charts.
- `dashboard/src/data/realData.test.ts` (new) — loads the **actual**
  `public/data/*.json` and asserts no non-finite values, missing→`null`,
  real zero kept, correct structure.
- `dashboard/tsconfig.app.json` — added `node` to `types` (needed by the
  fs-based realData test); `@types/node` added as a dev dependency.
- Regenerated all four dashboard JSON files and re-ran the research outputs.

**Missing vs zero — preserved, not invented.** No cleaned/processed CSV was
modified to drop or fill missing values. The fix only changes *serialization*
of values that already existed: structurally-missing coal prices (e.g. AK
2020 sector 3, US sector-98 2021) and state inventories export as `null`; a
real zero (e.g. CA 2020 sector-3 consumption = 0) exports as `0`. Original
CSVs untouched.
